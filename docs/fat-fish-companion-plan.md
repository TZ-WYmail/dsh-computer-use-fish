# 大肥鱼电脑操作伴随桌宠：分支修改方案（讨论稿）

日期：2026-10-26。本文是方案，不代表功能已实现或桌面兼容性已验证。

## 1. 已确认的体验方向

采用社区鲸鱼娘／DeepSeek 娘：蓝白发、蓝瞳、鲸尾、呆毛、蓝白女仆装，铁盆兼作饭盆和小头盔。性格可爱、调皮、略傲娇，喜欢白米饭和 Token。工作时跟随操作目标，空闲时停回桌面角落。

核心体验是让用户看懂“她正在观察哪个窗口、准备操作哪里、是否等待批准、动作有没有得到确认”。角色独白采用简短任务摘要和角色台词；不为每个动作额外调用模型生成文案。默认静音，音效另设开关。

推荐风格：Q 版软萌的 2D 全身角色；大脑袋、小短腿、肥尾巴、弹性压缩与回弹，适合小尺寸识别。实际使用已有素材还是补充绘制，以素材清单核验结果为准。

## 3. 参考项目与选型

### 首选参考：dsh-pet

https://github.com/PC2005-cloud/dsh-pet

该项目已使用目标“大肥鱼”形象，具备桌面透明窗口、动画候选池、会话工作状态、宠物包，以及位置和动画控制接口。适合参考其素材组织、动作调度、点击穿透和宿主／桌面进程分工，不需要重造整套动画播放系统。

有一个确定的兼容约束：本轮读取的 dsh-pet main 分支 package.json 明确将 Harness 0.1.7-rc.2 标为 incompatible，依赖面向 0.2.x。不能直接把最新版整包装进当前环境，也不应为桌宠直接升级现有 Harness。

建议采用“现有 computer-use + 薄事件桥 + 独立桌宠伴随进程”。先核对可用的兼容历史版本；若不存在成本合理的兼容版本，复用或适配可独立运行的渲染模块、宠物包和动画调度，避免引入完整的新宿主依赖。需要改动的参考渲染器应固定来源提交，保留许可证和原作者署名。

### Linux 窗口行为参考：Mochi

https://github.com/miflow13/mochi-desktop

Mochi 文档将 GNOME Wayland 作为主要测试环境，并使用 XWayland 桌宠窗口。可参考这一路线，但其文档也列出 Overview／工作区切换等生命周期问题。因此对本机优先验证 XWayland 透明伴随窗口；置顶、无焦点、点击穿透、缩放和移动能力都以本机实测为准。

不将需要 compositor 特定协议的桌宠方案直接视为 GNOME 通用实现。若桌面跟随受限，降级为屏幕角落的真实状态展示，明确标示“跟随暂不可用”。

## 4. 用户看到的完整流程

例：要求 DSH 在计算器完成 7 + 8。

1. 鱼娘从角落游向计算器窗口边缘，举望远镜：“我先瞅瞅。”
2. 找到按钮后，鱼鳍指向目标旁边；目标出现短暂描边。鱼的身体避开实际点击区域。
3. 点按时出现戳一下、尾巴轻拍或铁盆轻敲的随机变体；按键旁显示“准备点 7／正在点 7”。
4. 后台输入被明确拒绝时，鱼停止动作，举牌：“要借一下前台，可以吗？”真正的批准继续通过 Harness 审批流程完成。
5. 批准后重新检查窗口、观察有效期和取消状态，再执行一次前台输入。拒绝后收手，显示“本次操作已取消”。
6. 驱动只表示已发送时，显示“已操作，正在确认”；观察到结果为 15 后才进入庆祝动作。
7. 任务结束后甩尾、鞠躬或端饭盆庆祝，然后回到角落。默认只在步骤变更时更新气泡，连续快操作合并展示。

额外状态也各有多种动作：

- 空闲：吃饭、打盹、晃尾巴；离开角落前有起身过渡。
- 等待批准：举牌、抱盆等候、双鳍背后站定。
- 结果待确认：举小勾待盖章、歪头观察、翻验收小本。
- 成功：甩尾转圈、端盆庆祝、得意叉腰。
- 失败：铁盆扣头、尾巴打结、摊鳍解释；不能播放成功庆祝。
- 用户取消：刹车收手、举“收到”牌、退回角落。

按状态加权抽选，避免连续两次完全相同；失败、审批和取消的含义固定，随机性只改变表演。第一阶段按 36 个工具表现槽位加公共状态建立清单；通过复用姿势、表情和道具降低素材量，最终独立动画数量在素材盘点后确定。

## 6. 位置、坐标和不遮挡策略

鱼跟随操作目标，不追逐用户真实鼠标。优先停在目标窗口边缘或目标控件外侧，与实际操作点保持安全距离；目标标记与角色位置分别计算。

事件必须携带坐标空间、截图尺寸、窗口信息和显示器信息。桌面渲染使用屏幕逻辑坐标；窗口截图坐标、驱动输入坐标和桌面位置分别转换，不能复用一个缩放系数处理所有路径。保留已有 HiDPI 修正，并补充多屏、负坐标、分数缩放、截图降采样、窗口移动的验证。

元素有有效几何时才精确跟随；只有 token 时停在窗口边缘并说明“正在操作此窗口”，不猜控件位置。执行前确认窗口几何未变化；变化后重新观察。

桌宠默认点击穿透、不抢焦点；实际操作期间收起宠物交互菜单。鱼的管理入口放在 Harness 设置或托盘，提供“暂停任务”“隐藏桌宠”“回到角落”和大小设置；暂停需接入真实任务取消／暂停能力，界面反馈必须与实际能力一致。

截图前做遮挡检查。优先排除桌宠自己的进程和窗口；若截图仍包含桌宠，采用短暂隐藏、等待合成器刷新、截图后在 finally 恢复，并验证不造成焦点变化。桌宠不能成为模型误选的操作目标。

## 7. 代码修改范围

### 7.1 统一输入投递与审批（先做）

修复不仅是放开 supportsDeliveryMode。需要让键盘、坐标点击、滚动和拖拽实际进入统一投递器，并把审批上下文从工具入口传到各路径。

- 在 actions/human 调用路径之间提取公共投递器，覆盖经当前驱动 schema 确认可用的输入工具白名单。
- cua.js 保留进程退出码及结构化 JSON 错误；即使驱动非零退出，也能识别明确的 background_unavailable，而不是只剩一段字符串异常。
- 仅在后台明确拒绝且能确认动作尚未发生时申请一次性批准，再尝试一次 foreground。对超时、部分拖拽、结果未知和已发送但未验证的动作不自动重放。
- 审批后重检取消信号、当前目标、快照时效和已有权限。快照过期时重新观察并核对语义目标；无法确认则停止。
- AX 元素点击／输入保留可用的后台路径；无需因显示桌宠就切换到前台。
- move_cursor 等装饰性动作失败不能单独触发前台操作授权。

### 7.2 操作事件与桌宠桥

从真实工具执行流程发出：准备、审批等待、执行中、结果待确认、已确认、失败、取消。每个事件带 sessionId、actionId、工具类别、目标窗口标识、时间和递增序号；多会话默认绑定一只鱼只跟随一个活动会话，可手动切换。

本机通信优先使用带访问限制的本地 IPC，若复用现有桌宠接口则沿用其认证机制。默认只传动作元数据和简短状态，不传输入正文、截图、密钥或完整窗口内容。独立桌宠进程无执行电脑指令的权限；动作仍由 Harness 和驱动完成。

桌宠断连、动画文件缺失或渲染崩溃时，工具调用继续按原有结果运行。重连使用当前状态快照，丢弃过期动画，不重放电脑动作。

### 7.3 调度器和渲染器

新增事件适配、动画状态机、目标定位与宠物包清单。优先复用 dsh-pet 的相应设计；渲染器不直接依赖当前不兼容的 0.2.x Harness 服务。

优先级：取消／失败／审批 > 正在执行 > 结果确认 > 普通工作 > 空闲。高优先级可中断普通表演；动作预热、关键帧与真实执行事件同步，不能为了播完可爱动作拖慢电脑操作。连续打字或按键合并成短工作片段；设置动作冷却和减少动态效果选项。

拟增加或改动的文件分组：
- lib/cua.js：结构化驱动结果与错误。
- lib/actions.js、lib/human.js、index.js：统一投递器和上下文传递。
- lib/input-dispatch.js（拟）：单次审批及受限重试。
- lib/operation-events.js（拟）：动作生命周期事件。
- companion/（拟）：IPC、桌面定位、状态机和渲染适配。
- pets/fat-fish/（拟）：动作清单、素材来源与表现映射。
- tests/：审批、异常、状态和坐标相关回归验证。

这些是结构建议，落地前可根据选定参考版本调整。

## 8. 两项旁支问题的处理边界

app_launch 返回 launch_handoff_timeout 后，先短时间重新枚举窗口／应用并核对目标，已启动则报告实际状态，尚未确认则保留“不确定”；不立即重复启动，也不以“窗口出现”误判为界面已加载完成。

app_list 默认提供面向用户的应用与窗口列表，保留诊断开关查看完整进程；过滤内核线程时不能把所有缺少可执行路径的受限进程都当成内核线程。避免几百条 kworker 淹没模型上下文。

这两项适合作为独立提交，避免与桌宠渲染修复相互绑定。

## 9. 分阶段交付与验收

| 阶段 | 交付 | 通过条件 |
|---|---|---|
| P0 控制层修复 | 统一输入投递和结构化错误 | Linux 各输入工具遇到明确后台拒绝后，批准才前台重试一次；拒绝／取消零重试；无不确定动作重复执行 |
| P1 桌面可行性 | 静态鲸鱼娘 + IPC + 跟随原型 | 本机透明、置顶、点击穿透、目标不被遮挡、缩放定位均验证；不改系统会话 |
| P2 语义表演 | 12 工具动作映射 + 公共状态 | 每类至少三种表现；真实事件驱动；审批、待确认与成功可明显区分 |
| P3 真机联调 | 操作目标跟随与回归记录 | 计算器、编辑器、可滚动测试页面、拖拽测试面板逐项操作并观察实际效果 |
| P4 稳定与安装 | 退出清理、设置、兼容包和恢复说明 | 桌宠崩溃不影响 Harness；多会话不串动作；测试配置可恢复；重启可重现 |

真机验收包括：Escape／单键与组合键；截图坐标点击；上下滚动；拖拽起止；批准与拒绝；快照过期；窗口消失；隐藏与恢复；工作区切换；多屏／高分屏；截图无宠物污染。原 36 项检查必须继续通过，补充针对新投递路径的测试。

性能以可测目标控制：空闲尽量不轮询屏幕，静止动画降低帧率；动作事件延迟目标小于 100ms，不包含审批与驱动自身耗时。实际 CPU、内存和首帧时间在本机记录，未测前不承诺具体数值。
